Case Studies
A provider-agnostic bank aggregation pipeline
Fintech platform · 1M+ users · multiple countries
Problem

Users link accounts from many sources: global aggregators (Plaid, Yodlee), regional banks, open-banking OAuth banks and crypto exchanges. Each provider has its own auth, MFA, webhooks and failure modes, and refreshes were triggered from many places, which made failures hard to trace.

Approach
  • Every refresh trigger (manual refresh, login, post-link, provider webhook) funnels through one entry point into a refresh state machine (.NET), which I helped build; provider-specific code plugs in only after the machine selects the integration.
  • Provider webhooks hit an AWS Lambda behind API Gateway and are forwarded to SQS; the service only consumes queues, with no cron jobs and no inline calls from controllers.
  • Stalled refreshes are resumed by a delayed SQS self-message acting as a watchdog.
Trade-offs

Queues gave retries and isolation from slow providers but made debugging harder. I wrote a trigger map (every path that starts or resumes a refresh) and an end-to-end sandbox check (sandbox bank link → queue message → accounts created) that the team uses to diagnose "linked but no accounts" incidents.

Result

New providers are added without touching the trigger layer, and end-to-end processing time dropped.

Stack: C#, .NET 8, MongoDB, AWS Lambda, API Gateway, SQS, Plaid, Yodlee.
Setting up agentic development for a product team
Australian SaaS company · two squads
Problem

The team was adopting AI-assisted development under a working agreement: whoever merges owns the outcome, plan before code, no secrets in AI tools, AI usage recorded in PRs. Those rules lived in documents, not in the tools.

What I built
  • An orchestrator repo (no product code) that every Claude Code session loads: repo catalog, 26 per-repo skills and keyword routing.
  • 5 specialist agents: security review, ticket scoping, code search, documentation.
  • Hooks that block force-push, pushes to main, hook bypass and destructive resets, so guardrails are deterministic rather than prompt-based.
  • A shared "brain" so several concurrent sessions coordinate through file locks and messages.
Trade-offs

Guardrails live in hooks, not instructions: a prompt can be ignored, a hook cannot. Agents never merge; humans review the diff. Plan-first costs a few minutes up front and saves rework.

Team lessons

Agent orchestration makes coding fast, so ticket clarity becomes the bottleneck. An agent's "done" is not done: human verification in DEV is a required gate.

Result

The setup is packaged as a generator (bootstrap script, templates, versioned upgrades). I also contributed similar tooling (security-review agent, PR review triage, worktree tooling) to a fintech client's 130+ skill orchestrator.

Stack: Claude Code (skills, subagents, hooks, MCP), Bash, GitHub.
